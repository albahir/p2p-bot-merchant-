\# AGENTS.md — Bot P2P Binance (p2p-bot-merchant) Sistema automatizado de comercio P2P en Binance con arquitectura Fail-closed, verificación bancaria en tiempo real, gestión fiscal y notificaciones por Telegram. ## 🛠️ Stack Técnico y Estructura - \*\*Lenguaje/Entorno\*\*: Python 3.12+ / Docker Compose. - \*\*Librerías Clave\*\*: \`binance-sdk-c2c\` (API oficial P2P), \`httpx\`, \`tenacity\`, \`pydantic\`, \`sqlalchemy\`, \`streamlit\`, \`python-telegram-bot\`. - \*\*Bases de Datos\*\*: PostgreSQL / TimescaleDB (métricas) y Redis (cola de eventos e higiene de contexto). - \*\*Módulos Principales\*\*: - \`src/security/\`: Cifrado de credenciales (AES-256-GCM) y auditoría de logs. - \`src/core/\`: Cliente Binance, análisis de order book, estrategias de pricing y gestor de órdenes. - \`src/integrations/\`: Verificación de pagos bancarios (Open Banking/pasarela) y alertas de Telegram. - \`src/reporting/\`: Motor fiscal (FIFO / Costo Promedio), conversión BCV y exportación a Excel. ## 📋 Comandos del Proyecto - \*\*Tests Unitarios e Integración\*\*: \`pytest\` - \*\*Revisión de Estilo/Types\*\*: \`ruff check .\` &amp;&amp; \`mypy src/\` - \*\*Entorno Local con Docker\*\*: \`docker compose up -d\` - \*\*Ejecutar Makefile\*\*: \`make test\` | \`make lint\` | \`make dev\` ## 🛡️ Reglas de Seguridad Innegociables (La Constitución) 1\. \*\*Seguridad Primero\*\*: Permisos mínimos en API Keys (Solo \*Reading\* + \*P2P Trading\*) [8]. Whitelist de IP obligatoria [9]. 2\. \*\*Comportamiento Fail-closed\*\*: Ante cualquier timeout, error 5xx o ambigüedad, el bot SE DETIENE y alerta al humano. Nunca asume éxito [10, 11]. 3\. \*\*"Botón presionado ≠ pago confirmado"\*\*: Ninguna criptomoneda se libera basándose solo en el aviso del comprador en la app; requiere verificación bancaria directa [12, 13]. 4\. \*\*Límite de API Weight\*\*: Monitorear el header \`x-mbx-used-weight\`. Si supera 5,000, pausar peticiones por 60 segundos [14, 15]. 5\. \*\*Cero Secretos en Logs\*\*: Prohibido registrar API Keys, tokens de Telegram o credenciales bancarias en logs o excepciones [16, 17]. 6\. \*\*Sin RPA No Oficial\*\*: Solo utilizar la API oficial de Binance (\`binance-sdk-c2c\`) [18, 19]. ## 🔄 Modo de Trabajo (SDD &amp; TDD) - Lee \`docs/constitution.md\`, \`memory.md\` y la especificación activa (\`.specify/specs/NNN-\*/\` o \`specs/NNN-\*/\`) antes de modificar código [2, 20]. - Sigue \*\*Test-Driven Development (TDD)\*\*: Escribe la prueba unitaria/integración primero (rojo), verifica que falle y luego implementa la solución (verde) [21-23]. - Respeta la jerarquía de contratos: \`spec.md\` (requisitos) → \`plan.md\` (arquitectura) → \`tasks.md\` (desglose atómico de tareas) [24, 25]. ## 🚨 Límites de Autoridad del Agente - ✅ \*\*Permitido\*\*: Crear y modificar código dentro de \`src/\` y \`tests/\` respetando los requisitos de la tarea activa en \`tasks.md\`. - ⚠️ \*\*Requiere Confirmación Humana\*\*: Modificar el esquema de la base de datos, cambiar umbrales de estrategia de precios o alterar dependencias en \`pyproject.toml\`. - 🚫 \*\*Estrictamente Prohibido\*\*: Modificar la constitución (\`constitution.md\`), eliminar tests existentes sin justificación o intentar bypasses de la verificación bancaria.
